# PaperWeek

既存の `sumi468/PaperWeek` を拡張した、ブラウザで編集・保存・A4印刷できる予定表です。
フレームワークや本番用依存ライブラリの追加はありません。静的Webサーバーで
`index.html` を配信します。Firebaseの設定は [README-firebase.md](README-firebase.md) を参照してください。

## 日付の選択

- 「用紙・書式」→「表示・印刷する日付」で、開始日と1〜7日の日数を指定します。
- 「個別に選ぶ」ではカレンダー入力と「追加」で最大7日を選べます。日付チップの×で外します。
- 重複日付は追加できません。最後の1日は削除できず、常に印刷対象が残ります。
- 日付は昇順です。月末、年末、週をまたぐ指定にも対応します。
- 前後の矢印は、連続モードでは指定日数、個別モードでは1週間ずつ移動します。
- 「今週」で従来の月曜〜日曜の7日表示に戻せます。
- 予定フォームの日付と予定一覧は、選択中の日付に一致します。
- TODOは従来の週単位です。「TODO」タブの対象週で編集・コピーの対象を選べます。
  「先週の予定をコピー」は、この対象週へ先週の予定とTODOを追加します。
  印刷には選択日を含む週のTODOを掲載し、複数週なら週の日付を併記します。

## 印刷

- 3テンプレート、A4縦横、4種類の手書き量を維持しています。
- 手書き量を「アナログ重視」にしても、選択したテンプレートを維持します。
  時間軸を使う場合は「01 週間タイムライン」、リスト表示は「02 週間プラン」か「03 アナログ」を選びます。
- 横向きは選択した日数で幅を等分します。縦向きタイムラインは4日まで1段、5〜7日は2段です。
  縦向きプランは1日は1列、2日以上は2列で、最後の余った1日は全幅を使います。
- 画面プレビューと印刷は同じ用紙DOMを使います。印刷時は操作UIと縮小表示を除きます。
- 時間が重なる予定は横に並べます。枠内に収まらない予定・TODOや、設定時間外の予定は
  全文をA4の続きページに掲載します。長文は用紙内に収まる長さで分割し、過度に文字を縮めません。
- 通常はA4 1枚です。続きページが必要なときは、画面プレビューにも同じページが追加されます。
- ブラウザの印刷設定はA4、倍率100%、ヘッダーとフッターなしを推奨します。
  用紙の向きはアプリで指定してください。PDF保存も同じ印刷処理を利用します。

## 予定ファイルの取り込み

「予定」タブの「予定を取り込む」でJSONファイルを選び、日付・時刻・件数・保存先を確認して
「追加して保存」を押します。確認中やキャンセルした場合は保存しません。
ログイン中は表示されたアカウントのFirebaseに保存し、他の端末にも同期します。
ログインせずに使う場合は、保存先を「この端末のみ」に切り替えられます。
アカウントの読み込み中や通信エラー時に、端末への保存へ自動で切り替えることはありません。

予定リンクから開いた場合も、同じ確認画面で「JSONをダウンロード」または「追加して保存」を
選べます。ダウンロードだけでは予定を保存しません。リンクは `#paperweek=` にgzip圧縮した
UTF-8のJSONをbase64urlで含む形式です（圧縮後の文字列は64KBまで）。予定データはURLの
フラグメントからブラウザ内で読み込み、確認画面を開く際にアドレスバーから除去します。
予定データを公開リポジトリや配信ファイルに含める必要はありません。

既存の予定・TODOは残して追加します。同じ日付・予定名・開始・終了時刻の予定、または同じ
`sourceId` の予定が同じ週にある場合はスキップします。ファイル内の重複もスキップします。
取り込み済みの予定を変更したい場合はアプリから編集してください（取り込みで上書きはしません）。
Firebaseでは端末の保存待ちの編集を完了してから、対象週の最新データをトランザクションで読んで
追加します。表示していない週も対象にできます。通信失敗時は成功表示せず、再試行できます。
オフラインでのアカウントへの取り込みはできません。

「サンプルをダウンロード」から編集用の例を取得できます。形式は以下のとおりです。
個人の予定ファイルはGitHubへコミットせず、端末から選択してください。

```json
{
  "format": "paperweek-events",
  "version": 1,
  "timeZone": "Asia/Tokyo",
  "events": [
    {
      "date": "2026-11-09",
      "title": "サンプルの予定",
      "start": "09:00",
      "end": "10:00",
      "category": "other",
      "memo": "任意のメモ",
      "sourceId": "任意の一意な予定ID（繰り返し予定は各回を区別）"
    }
  ]
}
```

`date` は実在する日付、時刻は `HH:mm` です。日時はファイル記載のタイムゾーンでの時刻のまま
保存し、ブラウザのタイムゾーンへの変換は行いません。日をまたぐ予定・終日予定は、各日の開始・
終了時刻を持つ予定に分けてください。繰り返し予定は各回を個別の予定として記載します。
カテゴリは `school` / `study` / `club` / `work` / `family` / `private` / `other`。
`category`（省略時 `other`）、`memo`、`sourceId` は任意です。
1MB、500件、52週まで対応し、不正なデータを含むファイルは全体を取り込みません。
ICSファイルやiCloudとの自動同期には対応していません。

## データ互換性

予定は既存の `wp_week_v1_YYYY-MM-DD` にある `events` / `todos` のまま保存します。
`events[].day` は月曜0〜日曜6を維持し、データの移行や選択外の日付の削除は行いません。
予定のメモや未知の追加フィールドも、編集時に維持します。

表示条件だけを `wp_view_v1` に別保存し、端末ごとに保持します。
既存の書式設定 `wp_settings_v1` とFirebaseの書式同期は維持しています。
Firebaseは選択日を含むすべての週を購読し、不要になった週だけ購読解除します。
週をまたぐ予定の移動は元の週と移動先の週をそれぞれ従来の保存経路で更新します。
従来どおり、同じ週を複数端末から同時編集すると後の保存が優先されます。

## 検証

ビルドシステム・package.jsonは既存リポジトリにありません。

```sh
node --check app.js
node --check dates.js
node --check cloud-sync.js
node --test --test-isolation=none tests/dates.test.cjs tests/sync.test.cjs
node --test tests/import.test.cjs tests/import-sync.test.cjs
node tests/import-browser.cjs
node tests/browser.cjs
node tests/timeline.cjs
python tests/check-pdfs.py
```

単体テストはNode.js 24で確認しています。ブラウザテストにはPlaywrightとEdge、PDF検証には
Pythonのpypdfが必要です。本番用の依存関係には追加していません。
テスト環境のPlaywrightを `NODE_PATH` で指定できます。`PW_CHANNEL=chrome` でChromeに変更できます。
`PW_EXECUTABLE_PATH=/usr/bin/chromium` でインストール済みのChromiumも指定できます。
テストは使い捨てブラウザ・ローカルサーバーで実行し、Firebase通信を遮断します。
PDFとスクリーンショットはGit管理対象外の `artifacts/` に出力します。

検証対象は日付境界・夏時間・複数週同期のモック、保存データの保持、予定の追加・編集・削除・
日付移動、TODO操作、日付選択の復元、168通りの表示設定、320/390pxの画面幅、26種類のPDFです。
実アカウントでのFirebase同期、Safari/Firefox、スマートフォン実機、物理プリンターは未検証です。
取り込みは入力検証・重複・データ保持・Firebaseトランザクションの再試行と失敗を単体テストし、
ブラウザでは確認・キャンセル・再取り込み・保存先・通信失敗後の再試行・容量不足時の巻き戻しを検証します。
Firebaseの取り込み検証はモックを使用し、実アカウントへの書き込みは行いません。
週をまたぐ移動はFirestoreトランザクションではないため、2つの週への通信は独立して完了します。
